{% comment %} The timelapse picker, laid over the book rather than on a page of its own. Two tabs, and the order is the point: Lapse is where work gets recorded now and opens first, Lookout is the recorder this site used to run and sits behind it marked legacy. Everything Lookout could ever do is still in that second tab — starting a recording, picking a live one back up, attaching finished footage — it is just no longer the thing the book puts in front of you. The Lapse pane is deliberately empty markup: lapse_picker.js fills it from the Lapse API when the popup is first opened and again on every refresh, so a timelapse published while this page has been sitting open can still be taped in. It finds everything by id, so keep these in step with that script. The Lookout pane is the opposite — a finite list of rows we already hold, rendered here. The checkboxes carry form="new-lapse" so they submit with the compose form even though this lives outside it in the DOM. The two panes post under different names (lapse_timelapses / lookout_timelapses) because the two sources are named differently — Lapse sends its own ids, Lookout sends row primary keys — and create_journal must never mistake one for the other. {% endcomment %}
